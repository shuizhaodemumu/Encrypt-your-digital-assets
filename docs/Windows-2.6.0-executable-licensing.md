# Windows 2.6.0：EXE 与 DLL 整目录授权

## 使用
1. 将原始 EXE、DLL、配置及资源整理到一个独立文件夹，先确认原程序能够运行。
2. 打开 Packager.exe，创建或解锁发行密钥，点击“导入内容包”，选择主 EXE，确认整文件夹打包范围。
3. 生成内容 EXE，输出位置必须在源程序文件夹之外。子目录与空目录会保留；发行密钥和管理员 .olmeta/.josn/.request 不加入程序包。
4. 收件人打开加密 EXE，导出设备请求；管理员按原流程签发 LIC，收件人导入后启动程序。
5. 管理员记录、设备请求、LIC 默认沿用源 EXE 的文件名主体。包装 EXE 默认增加“授权”后缀，避免覆盖源文件。

## 运行行为
- EXE 类内容不启用看门狗、故障重启、全屏或开机自启动。原程序自己要求全屏等行为不由本工具改变。
- 按原目录结构恢复到独立临时会话，以主 EXE 所在目录作为工作目录，正常创建 Windows 进程。
- 关闭授权窗口或授权失效时结束该会话的进程树；正常退出后清理临时文件，不自动重启。可手动再次启动。
- 相对目录内写入的配置/数据属于临时会话，退出后删除；重要结果请另存到外部目录。无法立即删除的残留会在后续启动时重试清理。
- 不自动安装 .NET、VC++、服务、驱动或 COM 注册依赖；需要这些系统组件的应用仍须安装对应环境。需要提权的程序须以管理员身份打开授权包装程序。

## 实现与边界
目录通过 Stored ZIP 保留结构，再使用现有分块认证加密、设备绑定及 LIC 签名验证。解密和提取在后台进行，逐块检查授权。路径校验拒绝越界、重复及链接条目。Windows Job Object 只管理授权会话生命周期，不执行故障重启。

运行时需要在本地恢复可执行文件，具有足够本机权限的人仍可能提取明文；这不是无法提取的 DRM。不要把无关个人文件放进待打包文件夹。

## 验证
2026-11-11：单元测试 29 项通过、3 项交互媒体/Office 测试跳过。无害 EXE + 真 DLL 测试通过：未授权不启动，LIC 后加载 DLL、嵌套配置和空目录；无自启动项；父进程退出后子进程生命周期正确；全部正常退出无重启且清理；关闭授权窗口结束主/子进程并清理。未对任意第三方 EXE 做兼容性承诺。
